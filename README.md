# 键盘锁

清洁键盘时暂停键盘输入的小型原生 macOS 应用。SwiftUI + AppKit，黑白灰与深蓝配色；无第三方依赖、浏览器内核、账号或服务器。

## 下载与安装

**[下载安装包 · 1.0.3](https://github.com/DanieeHan/keyboard-lock/releases/download/v1.0.3/KeyboardLock-1.0.3-macOS-arm64.zip)** · [版本说明与校验文件](https://github.com/DanieeHan/keyboard-lock/releases/tag/v1.0.3)

适用于 Apple Silicon（M 系列）Mac，目标系统 macOS 13 及以上。当前为测试版，尚未进行 Apple 公证；旧版 macOS 与 Intel Mac 尚未实机验证。源码和安装包均公开，无需登录即可下载。

将下载的 ZIP 移到非 iCloud 同步目录，解压后将“键盘锁”放入“应用程序”，再打开并授予权限。这样可避免同步目录自动添加文件属性影响签名，也避免移动应用后需要重新授权。本地构建的安装包为 `dist/键盘锁.zip`；`dist/键盘锁.app` 仅为开发方便保留的副本，正式使用请从 ZIP 解压。ZIP 内附 MIT License。

建议固定使用 `~/Applications/键盘锁.app` 或 `/Applications/键盘锁.app`，保留一个日常使用位置。更新前先退出旧版本，再替换该位置的应用。

1. 首次使用点击“开启权限”，在系统设置中为“键盘锁”开启辅助功能权限。
2. 回到应用，选择 1／3／5 分钟，再点击“锁定键盘”。授权本身不会立即锁定。
3. 状态显示“已锁定”、键盘图形变蓝并开始倒计时后，可以开始清洁。鼠标和触控板保持可用，点击“结束清洁”或等待倒计时结束即可恢复输入。

1.0.3 保留必要功能文字：应用名、锁定状态、自动解锁、时间单位、操作按钮和简短状态标签。键盘图形表达锁定变化，宣传标题与重复说明不再常驻。细节放在悬停提示和信息弹窗，异常时显示简短错误。保留辅助朗读标签和键盘焦点边框。窗口为 480×480；沿用原生 SwiftUI / AppKit 和深蓝灰白配色，未使用外部界面模板。

关闭窗口或退出应用也会解除锁定。沿用 1.0.2 的修复：“开启权限”对同一构建只申请一次授权；之后变为“检查权限”，仅检查状态，不反复弹窗。需要打开系统设置时，点击“设置”。返回应用后会短暂自动检查授权结果。

当前版本是本机 Apple Silicon 测试版。构建默认使用固定的本地自签名证书，尚未进行 Developer ID 签名和 Apple 公证。目标最低版本 macOS 13；当前实际验证环境是 macOS 27.0.1。旧版本与 Intel Mac 尚未实机测试。

### 已授权却仍提示授权

早期版本使用的临时签名绑定具体构建。升级后，系统可能仍保留旧版本的授权记录；开关已开启，也可能无法匹配当前版本。仅切换开关可能保留旧记录。改用固定证书后，需要为这个新身份完成一次授权，后续沿用同一证书的更新保持身份一致。

1. 退出所有“键盘锁”窗口，确认最终版本已放在固定安装位置。
2. 打开“系统设置 → 隐私与安全性 → 辅助功能”，选中旧的“键盘锁”，点击减号删除条目。
3. 点击加号，重新添加该安装位置的“键盘锁”，开启权限。
4. 从同一位置重新打开应用，点击“检查权限”。完成迁移后，继续使用同一证书和安装位置。

权限由用户在系统设置中授予。应用和构建脚本不会修改系统授权数据库。构建所用的本地证书只创建一次，不加入系统信任列表。

## 功能边界

- 全局拦截内置、USB 和蓝牙键盘交给 macOS 的普通按键、修饰键，以及系统传递的媒体键，不逐个绑定设备。新连接的键盘同样经过全局输入路径；设备兼容性需要实机验证。
- 电源键、Touch ID、部分系统保留操作及硬件状态（例如 Caps Lock 指示灯）不保证可拦截。它不是物理断电，也不是防止他人操作的安全锁。
- 使用最早的公开 HID 事件拦截点；若系统拒绝该级别的拦截，保持解锁并显示错误，不自动降级到覆盖范围更弱的方式。
- 创建拦截器后检查系统实际注册的事件掩码，确认按键类别完整后才显示“已锁定”。
- 按键尚未松开或系统启用安全密码输入时，拒绝开始；权限失效、拦截中断、休眠、切换用户时自动解除。
- 鼠标事件保留，并移除清洁时可能按住的 Command／Shift 等修饰状态，确保解锁按钮可用。没有键盘解锁快捷键，避免擦拭时误触。

## 纯本地与资源占用

程序不记录、不存储按键内容；不含遥测、更新器或网络请求代码。本机保存窗口位置和“当前构建是否申请过授权”的标记，后者用于避免重复弹窗。

启动时，在创建应用对象之前使用系统进程策略拒绝 `network*`，限制进出站和本地套接字网络操作。设置失败就退出；限制只作用于本应用，不修改电脑网络设置，也不影响其他应用。

这个实现依赖 **Apple 已弃用的 `sandbox_init` 兼容接口及自定义策略格式**。当前系统已实际验证拒绝进出站连接，但未来 macOS 可能不再支持，届时应用会拒绝启动。不能仅凭未声明网络权限，宣称一个非 App Sandbox 应用无法联网。用于全局键盘控制的辅助功能接口与标准 App Sandbox 存在兼容限制，因此当前版本按本机独立应用交付，不是 Mac App Store 发布包。

性能记录（1.0.0，2026-11-01，Apple Silicon，macOS 27.0.1，Release，本机一次测量；新版本尚未重新测量）：

| 指标 | 结果 |
| --- | --- |
| `.app` 磁盘占用 | 约 336 KiB，使用系统自带框架 |
| 打开窗口并操作说明弹窗后的物理内存 | 约 35 MiB（`footprint`） |
| 同时测得 RSS | 约 72 MiB，含不同口径的映射页面 |
| 同次测量的峰值物理内存 | 约 81 MiB |
| 空闲 CPU 单次采样 | 0.0%，不是长期平均值 |

待机不创建键盘事件拦截器，也没有长期运行的周期计时器；授权操作后的检查最多持续 15 秒。锁定时每秒更新一次显示，安全计时器每秒检查四次，权限和拦截健康状态每秒检查一次。关闭最后一个窗口即退出。

## 开发与验证

安装 Apple Command Line Tools 或 Xcode 后，无需联网安装依赖：

```sh
./scripts/build.sh
./scripts/test.sh
./scripts/render-preview.sh
```

默认只构建当前电脑架构，生成 `dist/键盘锁.zip`，并保留 `dist/键盘锁.app` 开发副本。可选通用架构：

```sh
ARCHS="arm64 x86_64" ./scripts/build.sh
```

默认由 `scripts/local-signing.py` 创建并持续复用一个本地代码签名证书，存放于 `~/Library/Application Support/KeyboardLock/Signing`，不进入项目或同步目录。目录权限为 `0700`，证书、身份记录、密码和专用钥匙串文件权限为 `0600`。私钥在专用钥匙串中标记为不可导出，仅授权 `codesign` 使用；构建结束或失败时锁定该钥匙串。临时导入材料会被删除，不写入日志。

脚本不修改登录／系统钥匙串或证书信任设置。创建时如果系统把专用钥匙串加进搜索列表，脚本仅移除自己的新增项，保留其他程序的并发改动。既有身份缺失或损坏时构建失败，要求恢复原始备份，绝不悄悄生成新身份。请私下备份整个 `Signing` 目录；其中包含签名凭据，不要提交到仓库、附在 ZIP 中或分享给他人。

若已另有签名身份，可明确选择它：

```sh
CODE_SIGN_IDENTITY="现有代码签名身份的完整名称或 SHA-1 指纹" ./scripts/build.sh
```

默认身份要求同时匹配应用标识与固定证书指纹。二进制改变后仍满足同一要求，同名但不同证书的程序会被拒绝；脚本不覆盖或放宽系统生成的要求。指定身份不可用时直接失败。只有明确设置 `CODE_SIGN_IDENTITY="-"` 才使用临时签名，并提示更新后可能需要重新授权。本地证书提供稳定开发身份，不提供 Developer ID 或公证资格。[Apple 身份要求说明](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements)、[Apple 自签名说明](https://developer.apple.com/library/archive/documentation/Security/Conceptual/CodeSigningGuide/Procedures/Procedures.html)。

`python3 scripts/test-signing.py` 在临时目录验证两次独立调用复用同一身份、不同构建相互满足身份要求、同名错误证书被拒绝，以及损坏存储不会轮换身份。测试结束删除临时钥匙串与全部材料，不修改正式签名凭据。

如果 `dist/键盘锁.app` 正在运行，脚本仅生成并验证 ZIP，跳过替换该开发副本；无法检查运行进程时也会跳过。脚本不会替换“应用程序”中的已安装版本。

`swift scripts/GenerateIcon.swift` 可以重新生成图标。构建脚本在系统临时目录组装、清理 FinderInfo / ResourceFork 并签名，随后生成不携带扩展属性的 ZIP，再解压到临时目录验证签名。ZIP 是稳定交付文件；同步目录中的 `.app` 副本可能再次被附加属性，因此不以它作为最终签名验证对象。

主要文件：

- `Sources/KeyboardLock/ContentView.swift`：五种界面状态、键盘示意图、时间选择与帮助。
- `Sources/KeyboardLock/KeyboardLockService.swift`：权限、HID 拦截、生命周期和解锁。
- `Sources/KeyboardLock/LockPolicy.swift`：纯计时与事件处理策略。
- `Sources/OfflineGuard/OfflineGuard.c`：启动时禁止网络操作。
- `Sources/KeyboardLock/App.swift`：原生窗口、菜单和退出行为。

已验证：Release 编译、本地签名、32 项计时及事件策略断言、42 项权限流程检查（含 9 个独立进程的持久化验证）、测试子进程进出站被拒绝、界面的原生渲染、真实窗口时间切换及说明弹窗。1.0.0 已实测进入锁定和鼠标解锁，以及实际启动和空闲内存。渲染器只绘制界面，不会拦截键盘。

2026-11-01 已在本机完成固定签名的实际升级验证：用户为 1.0.3 构建 5 完成授权后，先成功锁定并用鼠标解锁，再更新至构建 6。两次构建的 CDHash 不同，但证书绑定的身份要求相同。新版从同一安装路径启动时直接识别授权，无须再次申请，并再次成功锁定及鼠标解锁。测试结束保持解锁，恢复默认 3 分钟。该验证覆盖系统授权延续与锁定生命周期，不替代下述实际按键及设备兼容性测试。

**尚未验证：** 实体按键是否被完整拦截、外接设备热插拔、媒体键、快捷键、权限撤销与睡眠时的设备行为。策略测试验证的是决策逻辑，不替代真实设备测试。

建议首次用 1 分钟测试：确认普通字母、Command／Shift 组合与媒体键不会影响其他应用；验证鼠标解锁和到时恢复；随后分别验证内置、外接键盘及锁定中接入设备。若系统显示中断或已解锁，停止擦拭后重新开始。

实现参考：[Apple CGEvent 文档](https://developer.apple.com/documentation/coregraphics/cgevent)、[Apple App Sandbox 兼容性说明](https://developer.apple.com/documentation/security/protecting-user-data-with-app-sandbox)。离线接口的弃用状态同时依据本机 SDK 的 `sandbox.h`。
